Setup Guide/Flashing Firmware
Chapter 02 · Firmware

Flash the AstrOs.ESP firmware.

Every node runs the same firmware — AstrOs.ESP, built with PlatformIO and ESP-IDF. Flashing over USB is a one-time bootstrap; once a board is running, future updates arrive wirelessly from the web app. First you'll prep an SD card, then flash each Metro over USB-C — either with a prebuilt binary or your own build.

Pick how you'll flash each board — the steps below update to match.

§Prepare the SD card

Each node keeps its scripts, configuration and staged firmware on a microSD card, so every Metro needs one. Format the card as FAT32 before first boot.

!
Only the master gets a config file

On the master node — and only the master — add a plain-text file named config.txt to the root of its card with the single line below. That line is what tells the board it's the master, so it talks to the server on UART 1. Leave every padawan's card without a config.txt — a node with no config file comes up as a padawan automatically.

config.txt · master card only
isMasterNode=true

Slot each prepared card into its Metro before powering it on — the firmware reads config.txt at boot to decide its role. (Once a node is paired you can also re-format its card from the web app.)

§Flash a prebuilt release

No toolchain required — download a ready-made binary and write it to each Metro over USB-C.

!
Grab the right file

Use the metro_s3-flash.bin — not lolin_d32_pro (a different board) and not metro_s3-app.bin (that one's only for over-the-air updates through the web app).

  1. 1
    Download the firmware

    From the AstrOs.ESP Releases page, download astros-esp-<version>-metro_s3-flash.bin — the merged full-flash image for the Metro ESP32-S3 (e.g. astros-esp-1.2.0-metro_s3-flash.bin).

  2. 2
    Connect the Metro over USB-C

    Plug the board into your computer with a USB-C data cable (not charge-only). The Metro has native USB, so it shows up as a serial port directly — no separate programmer needed.

  3. 3
    Flash it from your browser

    Open the Adafruit WebSerial ESPTool in a Chromium-based browser (Chrome or Edge — they support Web Serial). Click Connect and pick the board's port. In the first slot, set the offset to 0x0, choose the metro_s3-flash.bin you downloaded, then press Program. The merged image already includes the bootloader and partition table, so that single file at 0x0 is all you need.

    ✦
    Prefer the command line?

    The same image flashes with esptool:

    terminal
    esptool.py write_flash 0x0 astros-esp-<version>-metro_s3-flash.bin
  4. 4
    Reset, then repeat for every node

    Tap RESET when the flash finishes. Flash each Metro the same way — they all run identical firmware; only the master's SD card carries a config.txt.

!
Board won't connect?

Put it into the ROM bootloader by hand: hold BOOT0 (DFU), tap RESET, then release BOOT0 — and try connecting again. Also double-check you're using a USB-C data cable, not a charge-only one.

§Install the toolchain

  1. 1
    Install Visual Studio Code

    VS Code is the IDE the project is built around — the repo ships ready-made launch and task configs for it. Grab it from code.visualstudio.com.

  2. 2
    Add the PlatformIO IDE extension

    Open the Extensions panel (Ctrl/Cmd + Shift + X), search for PlatformIO IDE, and install it. PlatformIO manages the ESP-IDF framework and the Espressif toolchain for you — there's nothing else to install by hand.

  3. 3
    Clone the firmware repository

    From a terminal (or VS Code's built-in one):

    terminal
    # Grab the AstrOs.ESP firmware
git clone https://github.com/battlesloth/AstrOs.ESP.git
cd AstrOs.ESP
  4. 4
    Open the folder in VS Code

    PlatformIO detects platformio.ini and, on the first build, downloads the espressif32 platform and ESP-IDF framework. This first run takes several minutes and needs an internet connection — later builds are fast and offline.

i
Native unit tests (contributors only)

If you plan to run the host-side unit tests, you'll also need a C++ toolchain — on Windows that's mingw-w64 via MSYS2 (pacman -S mingw-w64-ucrt-x86_64-gcc), on Linux any recent g++. Not needed just to flash a droid.

§Build & flash a node

Connect the Metro to your computer with a USB-C data cable. The board has native USB, so it shows up as a serial port directly — no separate programmer needed. The firmware targets the metro_s3 build environment.

terminal · in AstrOs.ESP/
# Build the firmware
pio run -e metro_s3

# Build and flash it over USB-C
pio run -e metro_s3 -t upload

# Watch the serial output (115200 baud)
pio device monitor -e metro_s3

Prefer buttons? The PlatformIO toolbar at the bottom of VS Code has Build (✓), Upload (→) and Monitor (🔌) icons. Just make sure the environment switcher reads env:metro_s3 first.

!
Upload won't start?

The board normally auto-resets into its bootloader. If an upload hangs or fails, put it into the ROM bootloader by hand: hold BOOT0 (DFU), tap RESET, then release BOOT0 — and run the upload again. Also double-check you're using a USB-C data cable, not a charge-only one.

§Confirm it's alive

Open a serial monitor — the Adafruit WebSerial ESPTool has one built in, or run pio device monitor if you built from source. A freshly flashed node boots up and logs its startup sequence at 115200 baud on the USB-C connection — including whether it came up as Master or Padawan, as read from config.txt. If you wired up an SSD1306 OLED, it'll show the node's status too. Registering nodes, discovering peers and pushing each node's hardware config happen in the Pairing Nodes section.

✦
Flash every board the same way

All nodes run identical firmware — flash each Metro with the exact same metro_s3 build. There's no "master build" vs "padawan build"; the only difference is the config.txt on the master's card.

i
This is the only time you'll need the USB cable

From here on, firmware updates are handled entirely through the web app. AstrOs.Server flashes new firmware to the master over the serial link, and the master forwards it to every padawan over ESP-NOW — no USB, no PlatformIO. Hand-flashing is just for first-time setup or recovery.
